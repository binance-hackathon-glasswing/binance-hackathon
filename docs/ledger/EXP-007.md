# EXP-007 — Does the basket trend guard cut drawdown at an acceptable cost?

- Date / owner: 2026-10-16 / Keith (owner per IDEA-075 §15); criteria drafted with Claude
- Status: draft (criteria written before any run; they freeze when the team confirms IDEA-075 §16 O2, which must happen **before** the run. The result is due Oct 19, and its data ends at the Oct 16 close, so every input exists by then. Revised 2026-10-17 for review TRV-03 to TRV-05, before any run.)
- From: IDEA-075 §4.1 (trading plan v1, strategy S1)
- Hypothesis: on past bStock token data, over 10-session windows, the trend guard (95% / 60%, 5-session average, ±1% band) lowers the average maximum drawdown by at least 1 percentage point compared with a static 95% book, while lowering the average net return by no more than 0.5 percentage points.
- Variants compared:
  - **A (static):** 95% gross; opening buys and the final flatten only.
  - **Weights (both arms, point in time; TRV-03):** at each window's start, the IDEA-075 §5.1 rule applied to bars **before** that start only: σ over the last 60 sessions (at least 20; a name with fewer takes the median σ of the names that have 20), cap 0.30. A window starts only once at least one name has 20 earlier sessions. The production weights (frozen from the Oct 21 close) are never used here, so no window's weights depend on its own or later returns.
  - **B (trend guard):** as A, with the trend level of IDEA-075 §4.1: UP → 95%, DOWN → 60%, evaluated once per session close. **Execution (primary; TRV-04):** at the plan's first eligible time, the next session's open + 30 minutes (IDEA-075 §7, IDEA-054 calendar: 14:00 UTC while the US is on EDT, 15:00 UTC on EST). The fill price is the open of the first 1-hour token candle starting at or after that time (`bar=1H`; intraday history pages back with `after=`, participant-kit.md K6). If that bar is missing, use the next available 1-hour bar in the same session, and if none exists, the session close. Report how often each fallback was used. The opening buys and the flatten use the same rule.
  - Both variants have no LLM limiter, no red flags and no top-ups (only the opening, the level changes and the flatten trade), and both apply the declared ladder (3% / 8% / 12% → 40%). This is the only difference between them: B has the trend level.
- Data & periods: kit token candles only (`candles` endpoint, F-95): 1-hour bars, turned into one bar per US regular session (B3, D-09) for the signal and σ, and kept as 1-hour bars for execution prices, for the five eligible bStocks. From each name's first available session to the **Oct 16, 2026 close** (the last session before the Oct 19 result deadline; TRV-05). The snapshot is taken after that close, and nothing later is used. Every overlapping 10-session window in which all five names have bars. The trend state at a window's start is taken from the 5 sessions before it. Snapshot: the fetched candles are saved outside Git with their SHA-256 recorded here before the run (no private data in the repo, F-61).
- Costs: traded notional × 25 bp per side (inside the 13–56 bp Roll range, IDEA-012), plus $0.03 gas per swap at 200 USDT starting equity (F-93). Sensitivity: also report at 50 bp per side.
- Metrics, per window: net return, including the final flatten; maximum drawdown on session closes; whether the drawdown reached 8%; number of level changes. Report means and medians over windows, and a block bootstrap 90% interval (block = 10 sessions) for the A − B differences.
- Pass criterion (declared setting only: 5 sessions, ±1%):
  - **supported** if, at 25 bp, the mean max drawdown of B ≤ that of A − 1.0 pp, AND the mean net return of B ≥ that of A − 0.5 pp, AND the median number of level changes per window ≤ 2;
  - **not supported** if the mean max drawdown of B is not lower than A's, OR the mean net return of B < A's − 1.0 pp;
  - **inconclusive** otherwise, or if there are fewer than 5 non-overlapping 10-session windows in the history.
- Sensitivity (reported, not used for the decision, no tuning): windows of 3 and 10 sessions; bands of ±0.5% and ±2%; execution at the next session's close instead of open + 30 minutes (the earlier convention, TRV-04).
- Decision: supported → ship the trend guard as declared. Not supported → drop it; S1 runs with the trend level fixed at 95%. Inconclusive → the team's default from IDEA-075 §16 O2 (recommended: ship as declared).
- Caveats: few independent windows (the token histories are short, and the Oct 16 cutoff removes three sessions, so the "fewer than 5 non-overlapping windows → inconclusive" rule may apply); one market regime only; overlapping windows are not independent; simulated at candle prices, not realised fills (ledger rule 4).
- Review fixes (2026-10-17, before any run): TRV-03, point-in-time weights instead of the final frozen weights; TRV-04, execution at the plan's first eligible time, with next-close as a sensitivity only; TRV-05, data cutoff and O2 settled before the Oct 19 result deadline.
