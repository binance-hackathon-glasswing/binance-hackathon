# EXP-007 — Does the basket trend guard cut drawdown at an acceptable cost?

- Date / owner: 2026-10-16 / Keith (owner per IDEA-075 §15); criteria drafted with Claude
- Status: draft (criteria written before any run; they freeze when the team confirms IDEA-075 §16 O2, by Oct 19 at the latest)
- From: IDEA-075 §4.1 (trading plan v1, strategy S1)
- Hypothesis: on past bStock token data, over 10-session windows, the trend guard (95% / 60%, 5-session average, ±1% band) lowers the average maximum drawdown by at least 1 percentage point compared with a static 95% book, while lowering the average net return by no more than 0.5 percentage points.
- Variants compared:
  - **A (static):** 95% gross at the IDEA-075 §5.1 frozen weights; opening buys and the final flatten only.
  - **B (trend guard):** as A, with the trend level of IDEA-075 §4.1: UP → 95%, DOWN → 60%, evaluated once per session close, applied at the next session's close price.
  - Both variants have no LLM limiter, no red flags and no top-ups (only the opening, the level changes and the flatten trade), and both apply the declared ladder (3% / 8% / 12% → 40%). This is the only difference between them: B has the trend level.
- Data & periods: kit token candles only (`candles` endpoint, F-95), turned into one bar per US regular session (B3, D-09) for the five eligible bStocks. From each name's first available session to the Oct 21, 2026 close. Every overlapping 10-session window in which all five names have bars. The trend state at a window's start is taken from the 5 sessions before it. Snapshot: the fetched candles are saved outside Git with their SHA-256 recorded here before the run (no private data in the repo, F-61).
- Costs: traded notional × 25 bp per side (inside the 13–56 bp Roll range, IDEA-012), plus $0.03 gas per swap at 200 USDT starting equity (F-93). Sensitivity: also report at 50 bp per side.
- Metrics, per window: net return, including the final flatten; maximum drawdown on session closes; whether the drawdown reached 8%; number of level changes. Report means and medians over windows, and a block bootstrap 90% interval (block = 10 sessions) for the A − B differences.
- Pass criterion (declared setting only: 5 sessions, ±1%):
  - **supported** if, at 25 bp, the mean max drawdown of B ≤ that of A − 1.0 pp, AND the mean net return of B ≥ that of A − 0.5 pp, AND the median number of level changes per window ≤ 2;
  - **not supported** if the mean max drawdown of B is not lower than A's, OR the mean net return of B < A's − 1.0 pp;
  - **inconclusive** otherwise, or if there are fewer than 5 non-overlapping 10-session windows in the history.
- Sensitivity (reported, not used for the decision, no tuning): windows of 3 and 10 sessions; bands of ±0.5% and ±2%.
- Decision: supported → ship the trend guard as declared. Not supported → drop it; S1 runs with the trend level fixed at 95%. Inconclusive → the team's default from IDEA-075 §16 O2 (recommended: ship as declared).
- Caveats: few independent windows (the token histories are short); one market regime only; overlapping windows are not independent; simulated at session close prices, not realised fills (ledger rule 4).
