Kit history omits approvals and has no wallet transaction-count endpoint. The kit's fallback gas and nonce-increment demo behavior do not satisfy IDEA-021's conservative contracts.

Current primary docs checked by browsing (2026-10-10):

- [Binance wallet API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/wallet-api): detail exposes sender nonce, status and block height; the documented schema does not expose a canonical block hash/finalized-head proof. `X-OC-NONCE` is request anti-replay, not the wallet EVM nonce. Inspect actual responses before relying on this schema; a present transaction nonce is not a complete wallet transaction count.
- [Binance trading API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/trading-api): bStock RFQ routing may embed a short expiry. The broader API also documents RFQ order submission; that does not change this project's kit-specified local-signing transaction path, and this collector cannot invoke it.
- [Binance transaction API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/transaction-api): exact EVM payload gas estimation is a separate endpoint from broadcast. Gas estimation before approval may fail without proving the quoted route itself invalid.
- [BNB Chain API documentation](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/bsc-api-list/): a finalized block tag is documented. This suggests a candidate read-only chain adapter, **not verified service availability or registration**; no RPC endpoint is activated here. Additional chain service must be recorded in the manifest before production use (IDEA-021 ENG-06).
