## Code review of the combined revision `b26ca09` (R15–R24, 2026-10-11)

Requested by Yao Zhu: a correctness review of PR #7 at `b26ca09` (Claude Code `/code-review`), then fixes, tests and inline PR comments for teammate review. The review found ten defects that V14's suite did not exercise. Severity tags as in the red-team files (P1: could create an unauthorized trading effect, lose or duplicate durable state, accept wrong evidence or bias a verdict; P2: contract violation without a direct trading or verdict effect).

- R15 (P1): `RuntimePlanner._job` hashes only the payload into `job_id` but stores `due_ms = now_ms` and `valid_until_ms = now_ms + validity`. A later round that plans the same payload (an unchanged `STATEMENT_REVIEW_DUE` state version, or a policy review in the same session) sends the same `job_id` with different bytes; `PostgresStore._job` raises `IntegrityError` and the whole round commit fails. Fix: the job definition is a pure function of its payload. A statement review is due at the earliest `next_due_ms` of the listed statements (new `review_due_ms` in EvidenceView.v1/EvidenceContext.v1). A policy review is due at the first decision time the builder saw in that session (`session_anchor` in the projection, `session_started_ms` in the context).
- R16 (P1): `ContextBuilder` accepts the assessment into issuer evidence state in the same call that reads the ledger, calendar and market ports. When any of those raises, `Coordinator.start` sets `assessment=None, updates={}`, so an adverse finding in that result is never latched. Fix: the builder raises `ContextUnavailable` carrying the evidence updates; the coordinator commits them with the round and records the assessment, but still runs no policy.
- R17 (P1): `mandatory_reductions` runs only `problem()`; it skips the strategy's market usability, `STALE_EVIDENCE_VERSION` and `DUPLICATE_CONTEXT` checks and its universe. A context the strategy rejects can still force `max_units=0`. Fix: one acceptance function (`accept_records`) shared by `accept_for_strategy` and the builder's reduction path, fed the strategy's own parsed markets (`strategy.schema.market_view`), the persisted `evidence_versions` and the snapshot universe.
- R18 (P2): a due statement review only advances its attempts in `lifecycle.observe`, which runs only for ASSESSED results that contain the same statement. ABSTAIN, UNAVAILABLE or unrelated results never count, so the bounded review never reaches REVIEW_EXHAUSTED and jobs are re-planned on every state version. Fix: every accepted result at or after a statement's due time that did not observe it counts as one incomplete review attempt (`lifecycle.missed_reviews`).
- R19 (P1): the KRW suffix pattern's optional sign and `NUM_TOKEN` read the hyphen of a range ("1.2-1.5 trillion won") as a minus sign, so the upper bound is extracted and verified as −1.5 trillion. Fix: a hyphen directly after a number is never a sign, and a KRW suffix amount that is the second half of a hyphenated range is not matched as a point.
- R20 (P2): `prior_context` skips earlier filings with quality MISSING and documents whose fetch failed, yet still reports complete history, labelling statements FIRST_SEEN instead of HISTORY_UNAVAILABLE. Fix: an unreadable earlier filing or document leaves that metric's history incomplete and is recorded as `PRIOR_HISTORY_UNREADABLE:<accession>` missingness.
