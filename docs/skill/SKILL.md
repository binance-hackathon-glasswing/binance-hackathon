# Binance Agentic AI Challenge — Skill File (core)

## 0. Reading contract (for humans and LLMs)

### 0.1 Labels
Every line carries an ID and a label. Never upgrade a label silently.

| Label | Meaning | How to use it |
|---|---|---|
| `F-xx` FACT | Stated on the official DoraHacks page or its timeline image (F-01..F-80), or in the organiser-issued participant kit (F-90..F-105, cited by document and page). Quoted or near-verbatim. | Binding until the official rules say otherwise. The kit itself says the official competition rules prevail over it (F-90). |
| `T-xx` TEAM FACT | What the team's own drafts say (LARP proposal, answer sheet, deployment plan), or what the team transcribed from the application form. | True about *our plan*, not about the rules. Form fields are as transcribed by the team, not independently captured. |
| `E-xx` ENVIRONMENT | External evidence, graded: **[PRIMARY]** issuer/regulator/vendor's own doc, or the paper itself; **[ISSUER-EDU]** issuer's marketing or educational pages (official, not independent); **[SECONDARY]** press/aggregators; **[DEV-REPORT]** third-party developer repos/issues; **[ESTIMATE]** our arithmetic; **[UNCONFIRMED]**. | Plan around PRIMARY. Hedge the rest. **Never copy a SECONDARY/DEV-REPORT statistic into the proposal.** |
| `I-xx` INFERENCE | Reasoned from F/T/E. Each has **Basis**, **Counterpoints**, **Example**, **Confidence** (High / Med / Low), and **Proposal use** (whether it may inform proposal text). | Act on High. Design to survive Med/Low being wrong. |
| `H-xx` HYPOTHESIS | A claim about edge or behaviour that we intend to test, with a test plan and a kill criterion. | Never present as established. |
| `P-xx` PRINCIPLE | Design direction we recommend. Opinion grounded in F/E/I/L. | Default choices; change by explicit team decision. |
| `D-xx` DECISION | A choice the team still has to make. | Resolve by the named date. |
| `G-xx` GUARDRAIL | Behaviour imposed on our agent/team. Each is tagged **[RULE: F-xx]** (directly required by the official text), **[RULE-DERIVED]** (our conservative implementation of a rule whose exact reading is open), **[POLICY]** (a team choice, not required), or **[PRACTICE]** (engineering hygiene). MUST = enforced in code and tested. SHOULD = default; overriding needs a logged reason. `[brackets]` = placeholder. | Implement as written. Never describe a POLICY as a rule. |
| `Q-xx` OPEN QUESTION | Unknown that matters. Ranked. Where a conservative working assumption exists it is stated; where none is safe, the item is an **unresolved dependency** and the design must work either way. | Ask organisers. |
| `S-xx` STRATEGY OPINION | Contest-strategy views (tournament incentives etc.). Kept in Appendix A (now `larp/strategy-opinions.md`). | **Not evidence of proposal quality. Keep out of the proposal.** Revisit before final activation. |
| `L-xx` LITERATURE | Research evidence with citation and grade. | Justifies P/G items. |

**Status** (design commitments only; see the "v1.0 adopted scope" table in larp/plan.md): Proposed / Adopted / Implemented / Tested / Superseded. Status is separate from confidence: an Adopted design can rest on a Low-confidence inference.

### 0.3 Never do
Each line summarises the cited items; the items govern.
1. Never trade manually. Humans never sign, approve or submit wallet transactions and never choose trades. Human actions on the agent are limited to HALT, restart/resume after reconciliation, and deploying a registered version through a version event — each logged as an incident or version event [RULE-DERIVED pending Q-09]; no operator flatten unless Q-09 confirms. (F-48, F-60, F-64, G-08)
2. Never let a trade or transaction exist without a mapping to one registered version and one unique write-ahead decision record — failed txs included. (F-34, F-48, F-60, F-66, G-04)
3. Never add own or external funds, withdraw, transfer wallet-to-wallet, bridge, or make unrelated swaps or arbitrary contract calls. Never trade through the custodial Binance Agentic Wallet or Binance spot trading; orders go only through the Web3 Open API with local signing. (F-25, F-64, F-104, G-01, G-13)
4. Never use leverage, shorting or derivatives. Never trade any token except the five eligible bStocks (NVDAB, GOOGLB, SKHYB, TSLAB, MSFTB) against USDT; BNB only for gas. (F-64, F-91, F-93, G-02, G-13)
5. Never let anything trade unless its version is committed, pushed to the registered repo, manifested and logged in a version event, with a hash equal to the active manifest. (F-60, F-61, G-03, G-12)
6. Never force-push, rebase or rewrite the challenge branch; fix mistakes with a new commit. GitHub does not enforce this on our plan (no branch protection, checked 2026-10-03), so the rule itself is the guard. (F-61, G-40)
7. Never put secrets, keys or credentials in the repo or in logs, or private training/label data in the repo [RULE: F-61]. (F-61, F-62, G-06, G-41)
8. Never use future, non-public, Binance-internal, other teams' private or unlicensed data. (F-63, F-71, G-05, G-10, G-42)
9. Never backfill or rewrite logs; upload daily to write-once storage and buffer locally during outages. (F-62, G-07)
10. Never use a VPN or relay to get around geo-restrictions or IP checks. (F-70, F-71, G-17)
11. Never call a POLICY a rule: only items tagged [RULE: F-xx] are required by the official text. (§0.1, §0.2; tags in §7)
12. Never broadcast a swap whose `tx_hash` will not reach an ai-seeds round log; never log an approve as an order. Log every round, including hold-only rounds. (F-99, F-100, G-04)
13. Never run demo, example or test code with the registered wallet's ai-seeds credentials unless it is committed, manifested code: even quote-only runs upload real logs that auditors see. (F-103, F-60, G-03)

Contracts: NVDAB `0x02fca66c1d1afb4e2a7884261eb00f63598a7436`; GOOGLB `0x3f53de71c126bdabae20f9cd64848d317f6c3238`; SKHYB (SK Hynix) `0xca750ef65f295bbecd685abf54e82caf297bdb61`; TSLAB `0x5b1910eaad6450e50f816082aa078c41f10c292f`; MSFTB `0x80106cb3ead06659a5ad19df39d9b4733863b9b0`. - F-92 **Credentials and wallet.** (a) Web3 API Key + Secret from the Binance Web3 Developer Portal (create a project, email and phone verification; HMAC-SHA256 only); it "cannot move funds, but keep it secret". (b) "A dedicated BSC wallet: a new wallet used only by your agent and registered with the organizers"; its address is `AI_SEEDS_ADDRESS`; its private key or mnemonic signs transactions locally; "one agent per wallet". (c) `AI_SEEDS_SECRET`: "Issued by the organizers for that wallet"; a 64-hex-character string that signs log uploads. Trade only from the registered address. (Guide p.2, p.5; SDK PROTOCOL §2)
- F-93 **Funds and gas.** The wallet needs "USDT to trade, and some BNB for gas. Gas is paid only in BNB." "If you run low on BNB, swap a little USDT for BNB through the same quote-and-swap endpoint" (`toTokenAddress 0xEeee…EEeE`). In the organisers' tests one trade (approve + swap) cost 0.000022–0.000046 BNB (≈ $0.02–0.035 at BNB ≈ $756); SKHYB is the most expensive route. The demos refuse to trade below 0.002 BNB (a demo threshold). Who funds the wallets, and with how much, is not stated. (Guide p.2, p.5)
- F-94 **Chain and API conventions.** BNB Smart Chain, `binanceChainId="56"`. "Mainnet only, no testnet: every broadcast spends real funds and gas and cannot be undone." Base URL `https://web3.binance.com/build`. Amounts are integer strings in the smallest unit. "Only `code == 0` means success; HTTP 200 can still mean failure." Requests are signed `Base64(HMAC-SHA256(secret, timestamp + METHOD + "/build" + path + ["?" + query] + body))` with headers `X-OC-APIKEY`, `X-OC-TIMESTAMP`, `X-OC-SIGN` (optional `X-OC-RECV-WINDOW`, default 5000 ms, max 60000). Transactions are signed locally as legacy (`gasPrice`) transactions with `chainId = 56`; "the Open API only returns unsigned transactions". (Guide p.4–5)
- F-95 **Market data and market state.** `GET rwa/tokens` (`platformId=bstock`) returns `statusInfo` (`openState`, `marketStatus`, `reasonCode`, `nextOpenTime`): "When `openState` is False (here or in `rwa/underlying-market`), the market is closed or trading is halted: don't place orders." `rwa/price`: `tokenPrice` is the on-chain price in USD; `referencePrice` "is a derived per-share reference price, not an official stock market quote". `candles`: rows `[open, high, low, close, volume, timestamp_ms, tradeCount]`, oldest first, "only periods with trades". Balances: up to 20 tokens per call, `""` = native BNB. Transaction history: last 6 months; it does not include approves. (Guide p.6; Demo web3-open-api.md)
- F-96 **Execution flow.** `GET aggregator/quote-and-swap` returns a quote and an unsigned swap; `vendor="LiquidMesh"` is required and case-sensitive; `slippagePercent` or `autoSlippage=true` is required; `priceImpactProtectionPercent` defaults to 90. "Quotes are free and don't check balances." Every trade first approves the pay token "for exactly its amount" via `approve-transaction` (`vendor` = the quote's `vendorName`); the spender `dexContractAddress` "must equal the re-quote's `tx.to`". Wait for the approve's success, then re-quote: "bStock quotes use RFQ liquidity and expire after about 30 s" (expired → revert `DeadlinePassed`). The quote's `tx.gas` is a fixed 450000 while routes need about 450k–930k gas, so the swap uses `max(tx.gas, gas-limit estimate × 1.2)` from `POST pre-transaction/gas-limit`. Broadcast via `pre-transaction/broadcast-transaction`. (Guide p.7–8, p.10)
- F-97 **Confirmation, nonce and limits.** Only `txStatus == "success"` is success; `fail` = reverted (gas still spent); pending or no result = unconfirmed; after a 120 s wait "the transaction may still be mined". There is no nonce or allowance endpoint: the nonce is the highest nonce in the history + 1, or the last locally used nonce + 1 if larger. "No cancel: a swap either fills in full or reverts, and a revert still costs gas." Rate limits exist (HTTP 429, code 42900); quotas are on the Developer Portal, not in the kit. (Guide p.7–8, p.10–11, p.18)
- F-98 **Official Python SDK caveat.** `binance-web3-wallet` (6.x–7.0.0) "puts POST parameters in the URL and fails silently with 40001, so this guide calls the HTTP endpoints directly." (Guide p.11)
- F-99 **Decision logs (ai-seeds).** Each team "uploads one decision log per round with the ai-seeds SDK. The organizers audit every on-chain fill against these logs: tx_hash → the round log that recorded it → that round's input, chain of thought and output. A fill without a log cannot be shown to come from your agent." A round is "one complete agent run, from receiving its input to producing a strategy, however many model calls it makes". Log once per round, "including rounds that only hold (`orders=[]`)". Fields: `input` (everything given to the agent this round, e.g. system prompt, tool definitions, market and position context), `cot` (the chain of thought; with several model calls, all the reasoning in order), `output` (the final output), `orders` (the orders the code "finally decided to place this round (after risk checks …; not necessarily what the model output)"): `symbol`, `side` (`BUY`/`SELL`), `amount` (USDT spent for a buy, shares sold for a sell), `tx_hash`. `input`/`cot`/`output` must be non-empty. (Guide p.2, p.13; SDK README)
- F-100 **`tx_hash` rules and the daily check.** `tx_hash` is required once the swap has been broadcast, "whether it succeeded, failed or is still unconfirmed"; never for approve transactions; orders never broadcast (failed or blocked by risk controls) are listed without `tx_hash`. "Every day, all fills from the previous day are checked. A fill whose `tx_hash` is in no log is flagged for manual review." (Guide p.3, p.13, p.18)
- F-101 **Upload modes and deadlines.** Realtime (default): uploaded inside `log()`; on network errors, 5xx or 429 the log is spooled to `.ai-seeds/spool.jsonl` and re-sent about every 30 s; other 4xx raise `UploadError`. Batch: the previous UTC day's file is pushed 2–10 min after 00:00 UTC; "a day's logs must arrive before 02:00 UTC the next day. If they arrive later, the related fills are first flagged as 'fill without log'." "A normal return from `log()` does not mean the log was delivered." One `Client` per process; do not share `.ai-seeds/` between processes. Clock within ±5 min (`401 TIMESTAMP_SKEW`). Service `https://api.commonservice.io/ai-seeds-event-log`; it stores each log byte for byte and de-duplicates by event ID. Limits: ≤ 8 MB per log, ≤ 256 KB per stored record, files ≤ 10 MB / 100,000 lines. (Guide p.3, p.13–14, p.18; SDK PROTOCOL)
