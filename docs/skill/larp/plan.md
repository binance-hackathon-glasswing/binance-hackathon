## Summary (v0.3 §0.3)

The team's concept is **LARP (Liquidity-Aware Regime Planner)**: one central capability — turning verified, point-in-time catalysts into probability-scored long/hold/exit decisions (thresholds fit on validation data) that may abstain — supported by a regime-based exposure governor and a deterministic risk governor. Off-hours pricing of 24/7 bStocks is a *hypothesis to test*, not a claimed edge. Stage 1 is judged by people on feasibility, agentic depth, risk awareness, originality and ability to deliver; Stage 2 is mechanical % return; Stage 3 is a pass/fail audit of traceability. The largest proposal weakness is harness depth (the LLM currently has no tools, memory, planning or claim verification); the largest run-time risks are audit mapping (RFQ fills, non-trade balance events, version gaps) and day-0 gas.

## 6. CONCEPT AND DESIGN PRINCIPLES (development phase)

### 6.1 Scope: one central capability
- **Central capability (LARP):** turn *verified, point-in-time catalysts* into *probability-scored long / hold / exit decisions that may abstain* (target and abstention defined per I-63). "Reduce" exists only if the policy defines it (e.g., P(DOWN) in [θ_r, θ_exit) on a held name → reduce to [50]%); otherwise remove it from all text (D-06). The innovation claim lives here: evidence gathering and verification (harness layer) feeding a calibrated decision model (P(UP), P(FLAT), P(DOWN), calibrated on validation data, I-63) with a selection rule that may abstain (model layer).
- **Canonical flow:** agent → verified thesis → calibrated selective decision → deterministic risk → auditable execution.
- **Supporting control 1 — regime governor:** regimes are rule-defined per I-66 (pre-registered volatility/drawdown/[spread] rules); the governor sets the exposure budget and can veto entries; it is a risk control, not a second strategy. The learned regime classifier in T-12 runs in shadow only.
- **Supporting control 2 — deterministic risk governor:** limits, costs, freshness, allowlist (T-12, T-14).
- **Supporting control 3 — off-hours handling:** execution guard by default; entry logic only if H-01 passes.
- **Not claimed:** alpha, a fair-value model, or any return expectation (I-56).
- **Planning claim (review A P1 caveat):** proposal text must rest on what v1.0 builds — the agent choosing what evidence to fetch within G-50's bounded loop. G-52 may be only a static calendar; do not describe it as more (misrepresentation risk, I-35).
- Name note: "Liquidity-Aware Regime Planner" foregrounds the supporting controls (liquidity, regime), not the central capability; the team may keep it, but the first sentence of the proposal must name the central capability.
- Superseded: v0.2's "C1 + C2 + C3 synthesis" (three co-equal innovations) — dropped per I-55.

### 6.2 Harness additions needed for agentic depth (closes I-50)
All four keep the LLM away from trade authority and fit LARP's trace schema.
- **G-50 Bounded tool loop [POLICY].** The evidence LLM may make ≤ [6] tool calls per decision within [60] s; v1.0 exposes ≤3 tool types (retrieval first). Candidate tools: fetch filing section, fetch issuer release, search a second independent source, look up the name's historical reaction to similar catalysts (from our point-in-time store), query the feature store. Every tool call and result is logged in the decision record. Exceeding the budget → assessment returned as "insufficient evidence" → decision-model input marks low evidence quality.
- **G-51 Thesis memory [POLICY].** Thesis objects are written only after claim verification (G-53); memory reads may feed the evidence loop. Each open position stores a thesis object: catalyst, evidence IDs, expected horizon, falsifier conditions. Each cycle re-checks falsifiers against new evidence; a fired falsifier produces an exit candidate. After exit, a short post-mortem is stored and retrievable (with timestamps, G-35).
- **G-52 Catalyst planner [POLICY].** A calendar-driven planner schedules research ahead of known events (earnings dates once announced, E-41..E-47 macro releases) and decides which names get LLM attention each cycle; logged as a planning record.
- **G-53 Claim verification [POLICY].** A separate step checks that each claim in the evidence assessment cites an evidence ID whose content supports it (string/number match plus a second-model or rule check). Unsupported claims are removed; if the core catalyst claim fails → no risk-adding action (HOLD for non-held names, `hold_reason=EVIDENCE_UNVERIFIED`); held names still get the decision model on the remaining verified state, and risk-limit exits never need verification (P-09). A falsifier-driven exit candidate that fails verification is logged and re-checked next cycle; verification only vetoes or shrinks risk-adding actions (P-09).
- **G-54 Harness failure modes [PRACTICE].** Tool loop has hard timeouts, retry caps and a max-token budget; loops, schema failures or empty evidence resolve to HOLD with an incident record.
- Counterpoints: each addition adds latency and failure surface (L-52) and competes with I-55/I-58 for build time; keep the graph shallow (G-37); measure each addition's value in dev (H-02) and remove what does not help.
- **Build order and cut line [POLICY]:** G-50 (≤3 tool types, ≤ [6] calls per decision, retrieval first) and G-53 are required for v1.0; G-51 falsifiers required, post-mortems optional; G-52 may be a static calendar. Anything not green by Oct 22 is cut, not delayed. The proposal describes the v1.0 set only.

### 6.3 Principles (P)
- P-01 **Hold/cash is a legitimate, logged decision** (I-03). It is not free in every scenario (it forgoes gains in rising markets), so it must come from the policy, not from failure.
- P-05 **Every trade pays its costs.** Entry thresholds are set so that, on validation data, selected cases cleared estimated round-trip cost (entry cost + an explicit exit-cost assumption) plus a buffer (G-25); live entry costs come from the actual quote. State the cost convention explicitly (T-14); an entry-cost limit does not bound round-trip cost. Use a no-trade band so small signal changes do not cause trades (L-34).
- P-06 **Reason slowly, execute deterministically.** LLMs and classifiers produce inputs minutes-to-hours ahead; no model on the signing, limit-check, version-gate, logging, reconciliation or recovery path (T-12 already does this).
- P-07 **Sizing is simple and bounded.** Size from a defined volatility-scaled risk budget with hard caps (I-61, G-29). Do not commit to Kelly-style sizing: there is no validated payoff model or sufficient sample to estimate edge per trade.
- P-08 **Every thesis carries its own falsifier** (G-51).
- P-09 **Verification can only say no.** Verifiers veto or shrink; they never add or enlarge. Use external checks (tools, rules), not the same model re-thinking (L-50).
- P-10 **Write before you sign** (I-20).
- P-11 **Nothing trades that isn't registered** (I-23).
- P-12 **Point-in-time or it didn't happen** (I-36, I-37).
- P-13 **Humans may stop, never steer the wallet** (I-24, I-25).
- P-14 **Behaviour matches current declarations;** changes go through versions with reasons (I-35).
- P-15 **Capture the thinking you may be asked for** (I-29).
- P-16 **Harness over model choice.** Choose models for schema reliability, latency, cost and reasoning-trace access (L-12, L-13).
- P-17 **The dev wallet is a test budget** (I-39).

## 8. REFERENCE ARCHITECTURE (LARP + harness additions)

```
[Connectors] → point-in-time store (event_ts, retrieved_ts, source_uri, sha256)
   ↓ scheduled / planner (G-52)            ↓ event-triggered
[Local scoring: FinBERT relevance/sentiment]
   ↓                                       [Rule-defined regime governor (pre-registered volatility/drawdown/[spread] rules;
   ↓                                        learned regime model = shadow only)] ──exposure budget / entry veto──→ [Risk governor]
[Thesis memory (G-51)] ──READ──→ [Evidence LLM + bounded tool loop (G-50)]
   ↓ structured assessment (no actions)
[Claim verification (G-53)] — removes unsupported claims; rejected/unverified claims are still recorded in the decision record (F-49a thinking output, log completeness)
   ↓ verified claims only ──WRITE──→ [Thesis memory (G-51)]
[Calibrated decision model: P(UP), P(FLAT), P(DOWN)]
   ↓
[Selection gate: evidence quality, input coverage, confidence/margin] → eligible forecast, or ABSTAIN ──→ [HOLD record (G-38)]
   ↓
[Deterministic policy] → [Risk governor (G-20..G-30)] ── HOLD / veto ──→ [HOLD record (G-38)]
   ↑ risk-limit exits (G-22, G-25 exits): fresh quotes, bypass claim verification (P-09)
   ↓ approved intent
[Version gate (G-03)] → [Write-ahead decision record (G-04)] → [Signer service (G-01)] → Web3 API
   ↓ tx / order hash / fill
[Hash-chained journal incl. HOLD records → daily write-once bundle (G-07)]  [Reconciler (G-43)]  [Heartbeat/alerts]  [Recovery]
```
Recovery: replay the journal; find intents with no observed tx (write-ahead); never signed → `ABORTED_NOT_SUBMITTED` (I-20); an intent with no observed tx stays UNRESOLVED until the signed order's own deadline has passed and nonce/order-hash status confirms it is dead (G-18); idempotency keyed on observable identifiers (wallet nonce, quote ID, RFQ order hash, tx hash, API order status); decision ID is the internal key only (I-64, G-18); resume only after reconciliation passes.

## 4. INFERENCES (I) — LARP-specific

Format: **claim** · Basis · Counterpoints · Example · Confidence · Proposal use (Y = may inform proposal text; N = internal only).

### Leakage, rights and data (development)
- **I-37 Development evaluations that use an LLM on historical events are contaminated by memorisation.**
  Basis: L-20..L-24. For LARP: walk-forward splits and purge gaps protect the decision model from temporal leakage between splits, but **not** the hosted LLM's evidence step (T-12, T-15), which may already know how a historical catalyst played out. Counterpoints: LARP's LLM extracts structured fields and does not forecast direction, which reduces but does not remove the risk (judgements of "durability" or "novelty" can be coloured by known outcomes). Example: asked in validation to rate the durability of a 2025 earnings beat, a model trained on 2025–26 text may "know" the stock rallied. Mitigations: evaluate on events after the model's training cutoff; anonymise ticker/company/date in the evidence prompt (L-21); report both. Further counterpoints: anonymisation leaks identity for mega-caps ("a $4T GPU maker") — test by asking the model to name the firm; post-cutoff windows may contain fewer than ~100 usable catalysts, so report confidence intervals. Confidence: High. Proposal use: Y.
- **I-38 Data and model rights are an eligibility condition (F-71).** Keep a register with licences for every source and model. For LARP: GDELT, SEC EDGAR and FRED have public terms that must still be read; for Laya, architecture and licence are now publisher-stated (E-51: non-autoregressive, "never generates text", Apache-2.0), so T-11's "not a generative LLM" is consistent. Still unknown [UNCONFIRMED]: training data; pre-training cutoff (look-ahead in backtests before that cutoff, I-37); the revision to pin; financial-forecasting evidence (none — the card's benchmarks are generic); rights over the team's own label data (F-71); maintenance. The base model is near chance zero-shot and ships over-confident (E-51), so fine-tuning plus per-question-type temperature fitting by the team is the expected case: the model-layer claim (I-51) is then the team's own work, and F-49c becomes a handover of team-fine-tuned weights. Pin the upstream repo (convaiinnovations/laya) and a commit hash, not the aaroncool9 copy, which may be a re-upload. Name neither Laya nor Jev in proposal text; Jev is offline only. Confidence: High. Proposal use: Y (brief).

### Agentic depth, scope and claims (from the Stage 1 review; still govern the build)
- **I-50 Agentic depth is judged on "real reasoning, tools, memory, planning, verification" (F-40).** LARP's LLM currently makes a single structured call with no tools, memory, planning or claim verification (T-12); the decision model and rules are not agentic. The harness is strong on guardrails, observability and recovery. Risk: judges read LARP as "an ML pipeline with an LLM feature extractor". Counterpoint: F-31 says rules and classical ML "may support the system", and a conservative, auditable design scores on Risk awareness. As drafted, the LLM receives evidence *identifiers*, not evidence text (T-12), so evidence identifiers must resolve to content available to the evidence step (context builder or tool); adaptive retrieval — the agent choosing what further evidence it needs through the bounded loop (G-50) — is what adds agentic depth. Remedy (G-50..G-54): add a bounded tool loop, thesis memory, a catalyst planner and claim verification without giving the LLM trade authority. Confidence: Med-High. Proposal use: Y.
- **I-51 Model-layer work must be small, testable and ready early.** Build time is ~2 weeks after ~1 week of onboarding (F-12, F-13). LARP's calibrated decision model with a selection (abstention) rule is a credible model-layer piece if the prediction target, horizon and label definition are stated. A fine-tuned or self-hosted model also triggers the F-49c artefact handover. Confidence: Med-High. Proposal use: Y.
- **I-52 Declare a coherent risk framework with concrete initial values, and say the values are versioned configuration.** See I-35. Counterpoint: vague ranges can read as low risk awareness; concrete numbers read better if they are also enforced in code. Confidence: Med. Proposal use: Y.

### Decision semantics and risk arithmetic
- **I-61 LARP's "1% equity risk budget per position" is undefined until the risk measure and horizon are stated.**
  Basis: T-14. Example with an assumed definition (risk = 2 × σ over a 5-trading-day holding horizon): a name with 2.5% daily volatility has σ₅ ≈ 2.5% × √5 ≈ 5.6%, so 2σ ≈ 11.2% and size ≈ 1% / 11.2% ≈ 8.9% of equity; an index token with 1.2% daily volatility gives 2σ₅ ≈ 5.4% and size ≈ 18.6%. Consequences: at 2.5% daily vol four names ≈ 36% gross; at 1.5% (≈14.9% each) ≈ 60%; names or index tokens at ≤ ~1.1% daily vol hit the 20% per-name cap (1.0% → 22.4% before the cap). Which caps bind depends on the universe (Q-19); the 2.5% figure is an assumption, not a measurement. Also define whether σ uses the underlying's sessions or the token's 24/7 series. Counterpoint: a different definition (1σ, or a stop distance) changes sizes by ~2×. Confidence: High that the definition is needed. Proposal use: Y (define it in one line).
- **I-62 LARP's drawdown rules stop new risk but do not reduce existing risk.**
  Basis: T-14 (no new risk after an 8% peak-to-trough drawdown, "exits still allowed"); another draft passage reads "reductions and exits remain available" — the drafts differ (D-06). Example: peak equity 100 = 80 holdings + 20 cash. An 8% drawdown means holdings fell 10% (to 72; now 78% of equity). A further 10% fall costs 7.2 → equity 84.8, a 15.2% total drawdown. At I-61's typical ≈36% gross the same moves give 3.6% and then ≈6.8%, so the 8% halt may never trigger. Gap risk: a 20% position gapping −15% costs 3% of equity in one print, which the daily-loss check sees only afterwards. Counterpoint: forced de-risking crystallises losses and can whipsaw; the choice is a POLICY. Remedy option: an automatic reduction step at a deeper level (G-22). Confidence: High (arithmetic). Proposal use: Y (state which behaviour is intended).
- **I-63 The decision-model target must be defined before any calibration claim.**
  Required: (a) horizon h (e.g., next [5] US sessions); (b) price series — bStocks exist only since ~Jun 2026 (E-02), so training labels will mostly come from the *underlying* US shares while live actions are on the token; basis risk (off-hours token moves, Multiplier adjustments E-05) must be checked on the few months of token data; (c) classes, e.g., UP = r_h > +(c + b), DOWN = r_h < −(c + b), FLAT otherwise, with c = round-trip cost and b = buffer; (d) absolute vs index-relative return; (e) **ABSTAIN is not an outcome class** — it has no ground-truth label, so "calibrated P(ABSTAIN)" is undefined; implement abstention as a selection rule (selective classification, arXiv:2110.14914, cited by LARP) and calibrate only the UP/FLAT/DOWN vector; (f) action semantics: FLAT or ABSTAIN on a held name → HOLD (+ falsifier re-check, G-51); DOWN on a non-held name → no action (no shorting). Counterpoint: only the high-P(UP) tail trades, and it rests on few samples — report reliability for that bin with a bootstrap interval, not only overall calibration error. Confidence: High. Proposal use: Y (one line: target, horizon, abstention rule).
- **I-66 A learned regime classifier cannot be validated live and is hard to calibrate at all, so v1.0 uses rule-defined regimes (learned model = shadow only).** Regimes are latent; rule-defined labels make a classifier redundant, and after-the-fact labels use look-ahead; "dislocated" may have fewer than ~10 historical episodes; the live window may contain too few transitions for meaningful validation. Policy: define regimes by pre-registered rules on realised volatility, drawdown and [spread] thresholds; validate the *exposure effect* with a block bootstrap over historical stress episodes; report the episode count; do not call the regime model "calibrated". Confidence: High. Proposal use: Y.

## 5. HYPOTHESES (H) — to be tested, never claimed

- **H-01 Off-hours pricing.** *Claim:* when the US market is closed, verified information that arrives after the close is not fully reflected in executable bStocks quotes, and the gap can be captured after costs.
  Supporting evidence: off-hours trading is substantial (E-04, SECONDARY); routes switch between RFQ and AMM (E-13, DEV-REPORT). Against: weekend prices reportedly anticipate most of Monday's move (E-04, SECONDARY), which suggests efficiency; off-hours spreads, depth and the valuation source are unknown (Q-04, Q-29); our only 285 bp example was a perp, not a token (E-06).
  Test (read-only quotes, no fair-value model; fixed quote size [q] and fixed observation times; missing quotes recorded, not dropped; catalysts deduplicated so one event counts once): for each verified post-close catalyst, record the executable token buy quote at detection time t₀ and the executable token sell quote at [US open + 30 min]; the after-cost difference is the observation. Weekend statistics in E-04 are SECONDARY and not used.
  Result states (pre-registered): supported = n ≥ [20] observations and mean after-cost gain > 0 with a one-sided bootstrap p < [0.05]; not supported = n ≥ [20] and that criterion fails; inconclusive = n < [20]. Quote-simulated returns are not realised returns. **Sample reality:** the dev phase has 2 weekends (Oct 17–18, Oct 24–25) and ~9 weeknight closes, and only some will carry a verified catalyst, so n ≈ 0–10 and the expected result is inconclusive, not a failure. **Therefore v1.0 ships with off-hours logic as an execution guard only** (avoid trading into wide off-hours spreads; mark positions from executable quotes); logging continues during the run for a later decision. Proposal wording: "we will test"; never "we exploit".
- **H-02 Verified catalysts improve decisions over no-news baselines.** *Claim:* the decision model with structured evidence beats a no-evidence decision model at matched coverage, after costs. Test (pre-registered): metric = after-cost mean return of selected cases minus the baseline's at matched coverage, on post-cutoff walk-forward data (I-37); report calibration (Brier/reliability for the traded bin, I-63), coverage and confidence intervals. Pass: CI lower bound > 0. Sample warning: post-cutoff windows for recent models may hold only a few months. Pre-registered variants: (V0) baseline — the no-evidence decision model at matched coverage, with inputs, sizing and exits stated [D-07]; (V1) evidence-assisted prediction; (V2) evidence-only veto on V0. Each is evaluated on held-out data against its own pre-registered criterion; training, calibration, threshold selection and final evaluation use separate periods; compare at predefined coverage; report uncertainty for the traded subset. Result states: supported / not supported / inconclusive. A variant ships only if it was itself evaluated; veto effectiveness is not inferred from V1 failing. Inconclusive (the likely outcome given few post-cutoff months) → [pre-registered default, D-08]. Switching off the declared central capability is a version event with a stated reason and may need re-declaration (I-35, G-11). Keep evaluation offline; do not build three live variants.
- **H-03 Regime gating reduces losses in stress periods.** A rule-defined regime governor has no LLM memorisation issue, so a post-cutoff split is not the relevant test. Test: block bootstrap over historical stress episodes (I-66), comparing drawdown and coverage with and without gating and against the simple volatility-cap baseline; pre-define the acceptable coverage/exposure effect [x]; report independent episode counts. Result states: supported / not supported / inconclusive (too few independent episodes). Kill: if gating does not beat the volatility cap on drawdown at the pre-defined acceptable coverage, replace it with the simple volatility cap.
