### 3.2 Execution path: Binance Web3 API
- E-10 [PRIMARY] Web3 API launched 2026-06-17 (Binance announcement a9f19002…): "get aggregated swap quotes from multiple vendors, execute token swaps, and broadcast transactions on-chain"; "the API returns unsigned transactions — users sign locally in their own wallets"; "Zero Service Fees and No Positive Slippage Charge (for a limited time)"; MEV "protection cannot be guaranteed in all market conditions". Portal: web3.binance.com/en/dev-portal.
- E-11 [PRIMARY] Python SDK `binance-web3-wallet` v7.0.0 (2026-09-18); base URL `https://web3.binance.com/build`; WebSocket `wss://web3-stream.binance.com/w3w`; RSA or ED25519 signing (one dev repo reports HMAC — confirm at onboarding); official example `quote_and_build_swap_transaction(binance_chain_id="56", …, vendor="LiquidMesh")`. [UNCONFIRMED] no rate-limit table found. **Kit 2026-10-05:** the Open API signs with HMAC-SHA256 only (F-92, F-94), and the SDK's 6.x–7.0.0 POST calls fail silently with 40001 (F-98); the kit calls the HTTP endpoints directly. The SDK and WebSocket are not used in the kit, and this repo dropped the SDK dependency on 2026-10-05.
- E-12 [DEV-REPORT] Endpoints seen in hackathon repos: `rwa/tokens`, `aggregator/quote`, `aggregator/approve-transaction`, `pre-transaction/simulate` (others unconfirmed); routes "LiquidMesh SWAP" and "PcsXRfq"; quote validity ~30 s in one repo (another uses its own 60 s cutoff). **Kit 2026-10-05:** confirmed and extended by F-95..F-97 (`quote-and-swap`, `approve-transaction`, `pre-transaction/gas-limit`, `broadcast-transaction`, `transaction-detail-by-txhash`, `transactions-by-address`); bStock quotes expire after ~30 s (F-96).
- E-13 [DEV-REPORT] "Every bStocks and Ondo quote is LiquidMesh `SWAP`, but the filling venue switches between RFQ makers and AMM-style pools"; `referencePrice` is "token price divided by the token-to-share ratio" (oneticker README). "An RFQ fill is an EIP-712 order that a market maker settles" (ottopus issue #59, 2026-09-24). **Kit 2026-10-05:** bStock quotes "use RFQ liquidity" (F-96), but in the kit's flow our wallet signs and broadcasts the swap itself; no maker-settled EIP-712 order path is exposed.
- E-14 [PRIMARY] Web3 API prohibited regions: US and territories, Canada, Netherlands, Iran, Cuba, North Korea, Crimea, DNR, LNR, UK, Japan (conditional). **Singapore is not listed.** "IP checks are enforced on both the Developer Portal and the API server side."
- E-15 [DEV-REPORT] "`40304 "compliance restriction"` came back from US, Singapore and Netherlands servers, but not from a French exit" (oneticker README; date not shown). Update 2026-10-03: not reproduced for the supported-chain endpoint from the team's Singapore network (IDEA-001 §2).
- E-16 [SECONDARY] Binance.com restricted Singapore users from 2021-10-26 (Forbes 2021-09-28). [ISSUER-EDU] Binance Agent OS hackathon "not available to users in … Singapore" (Binance blog 2026-09-04).
- E-17 [PRIMARY] BSC block time "approximately 0.45 seconds" (Fermi hard fork, 2026-01-14); "0.05 Gwei standard gas price"; typical tx "around $0.005 or less"; gas paid in BNB. [ESTIMATE] a swap of 150k–300k gas × 0.05 gwei = 7.5–15 µBNB ≈ $0.008–0.02 at BNB ≈ $1,000–1,300. **Gas is small relative to spread/slippage**, but a wallet with zero BNB cannot transact. **Kit 2026-10-05:** the organisers measured 0.000022–0.000046 BNB (≈ $0.02–0.035 at BNB ≈ $756) per approve + swap; the NVDAB, GOOGLB, SKHYB and MSFTB swap routes need about 450k–930k gas, above the quote's fixed 450,000 (F-93, F-96).
- E-18 [PRIMARY] The Binance Agentic Wallet ("MPC Keyless"; user-set daily limit and token scope) is a different product from the Web3 API. Binance's Aug 17–Sep 1, 2026 bStocks AI PnL contest scored realised PnL by FIFO and banned wash trades and "activity between wallets controlled by the same entity". Which wallet model this challenge uses is not stated; F-22/F-24 ("your wallets and keys", Binance does not hold keys) suggest self-custody. **Kit 2026-10-05:** the challenge uses a self-custodied wallet with local signing; the custodial Agentic Wallet may not be used as the trading channel (F-92, F-104).
- E-19 [SECONDARY] Jeff Li (Binance VP of product): "We really cannot see the reasoning of what the user's action is." (TechCrunch 2026-08-20) — context for why F-49 asks for thinking output.
- E-20 [SECONDARY] Binance Seeds Program (launched ~2025-04-01): Pioneer Talent Program (full-time, ≤5 years' experience) and Accelerator Program (3–6-month projects for students/graduates) (ChainCatcher). No Binance primary found.

### 3.3 Reasoning-trace availability (bears on F-49a)
- E-30 [PRIMARY] Anthropic: "No `display` setting returns the raw chain of thought." `"summarized"` returns a summary produced by a different model; `"omitted"` returns an empty thinking field (full thinking encrypted in `signature`). `"omitted"` is the default on Fable/Mythos 5.x, Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5, Opus 4.8, Opus 4.7, Mythos Preview; `"summarized"` on Opus/Sonnet 4.6 and earlier.
- E-31 [PRIMARY] OpenAI reasoning models: "reasoning tokens are not visible via the API"; summaries via `reasoning.summary`; `encrypted_content` when not stored. gpt-oss (open weights) emits raw CoT in the `analysis` channel.
- E-32 [PRIMARY] Gemini returns thought summaries ("synthesized versions of the model's raw thoughts"); default depends on API surface. **DeepSeek's hosted API returns CoT in `reasoning_content`.** Qwen3 open weights emit `<think>…</think>` text.
- E-33 [UNCONFIRMED] The model name "GPT-6 Sol" and its behaviour were not checked; assume E-31 applies. With response storage disabled, OpenAI reasoning items come back as `encrypted_content` (E-31), which neither the team nor Binance can read, so they cannot serve as F-49a thinking output; readable text exists only if `reasoning.summary` is requested; a multi-turn tool loop (G-50) must pass the encrypted items back each turn and log them, because complete request/response records (F-49c) then exist only in our logs. The Laya card states it never generates text (E-51), so it contributes no thinking text; F-49a thinking text must come from the evidence step, and the decision's audit explanation is the probability vector + policy trace + verified evidence (I-29). **Kit 2026-10-05:** the kit says not to pass `encrypted_content` or `redacted_thinking` as output, and takes `cot` from readable summaries (F-102).

### 3.6 Models
- E-51 [PRIMARY — publisher claim] **Laya** model cards https://huggingface.co/aaroncool9/laya and upstream https://huggingface.co/convaiinnovations/laya (publisher Convai Innovations; code https://github.com/NandhaKishorM/laya); licence apache-2.0 on both. Claims: "non-autoregressive System 1 decision model" that "never generates text"; ModernBERT-large backbone (395M, bidirectional, fully fine-tuned) + decision head trained from scratch; 421M parameters (English); input = a state (text/email/ticket/JSON) + typed questions → typed answers with calibrated probabilities in one forward pass. Base `laya`: "Near chance on typed-decisions zero-shot — 0.362 here and 0.352 for multilingual" (random 0.318, majority 0.461, per the red-team read); "Ships over-confident: refitting one temperature per (question type, option count) moves mean ECE 0.466 → 0.081". The 0.766 typed-decisions accuracy belongs to the separate checkpoint `laya-typed-decisions` (fine-tuned on that benchmark's train split), whose card says: "Expect it to behave like the base `laya` checkpoint, or worse, on anything else." Jev 1.13.0 (published): 0.727. Not stated: training data, pre-training cutoff, commit/revision. No financial-forecasting evidence. Accessed 2026-09-30; checked: model-card text only (weights not inspected, no experiment run).
