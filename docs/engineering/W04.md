# W04 — approve/swap execution component

Owner Isaac; reviewer Keegan. `larp/execution.py` implements the W04 machine against explicit ports. Tests use `tests/execution_fixtures.py`; the SQLite implementation is a temporary offline fixture, not W02's production database. Preregistration/results: [EXP-006](../ledger/EXP-006.md).

## Contracts and boundaries

Immutable identity binds run, round, decision, economic intent, registered-version identifier, reservation identifier, wallet and chain. Economic uniqueness excludes round/decision so a new parent cannot duplicate an existing intent. One active economic intent per wallet/chain is enforced by the transactional store, across run IDs. The component consumes externally reserved/risk-authorized quantities; it creates no portfolio ledger or resource reservations.

Steps are approve then swap, with one immutable authorized attempt each. Preparation validates encoded swap economics even before approval, estimates the exact step payload, and applies integer 20% gas padding without a fallback. Approve calldata gets canonical selector/length/spender/amount checks. Swap validation delegates to a byte-bound verified decoder; the only supplied decoder understands explicitly fake calldata. After finalized approve success, preparation fetches a new quote and current nonce evidence. No local nonce increment is implemented.

Transitions: PREPARED → AUTHORIZED → SIGNED_DURABLE → BROADCAST_ATTEMPTED → PENDING/UNKNOWN → INCLUDED_SUCCESS/INCLUDED_REVERT → FINAL_SUCCESS/FINAL_REVERT. Provisional outcomes may regress; terminal states require canonical finalized evidence from the outcome adapter. Failed or absent evidence preserves the wallet barrier. Probe budgets/next-probe UTC times persist, and exhausting a budget does not clear a transaction. Replacement is disabled. Signed payloads can be reconciled after expiry or market closure but cannot be broadcast under failed guards.

`Store.commit` must atomically compare execution revision, ownership epoch and shared state version, enforce wallet uniqueness, and persist the event/state together. Production W02 must integrate this boundary with reservations and commands. Signer/broadcaster must recheck epoch/state version at their release boundary; no database transaction spans external I/O. Previously emitted bytes cannot be revoked by fencing. Fake signer persists immutable attempt bytes in its restricted fixture registry; public events contain only identity/hash/status metadata.

Outcome evidence binds transaction hash, sender and nonce, plus canonical block hash, block height and verified finalized head. The fake adapter supplies synthetic evidence; this is not an independently implemented chain-proof verifier. W08 has not proved a live adapter. Final events are idempotent observations for W03's settlement reducer, not actual accounting or reservation releases. W06 must map possible-broadcast swap hashes into immutable round records and keep approvals out of orders.
